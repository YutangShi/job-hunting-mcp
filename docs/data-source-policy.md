# 資料來源與使用政策

## V1 存取方式

V1 以 104 公開職缺搜尋為目標，沿用 [mozzan/job104-mcp](https://github.com/mozzan/job104-mcp) 的技術路徑：呼叫 104 網站使用的 JSON 搜尋／詳情端點，並使用 `curl-impersonate` 相容 HTTP client 提供瀏覽器 TLS／HTTP2 指紋。這是對目前網頁行為的相容整合；端點、欄位與存取結果可能變動。

HTTP 請求只由 104 adapter 發出。adapter 使用固定來源 host、合理 timeout、每來源節流和分頁上限；驗證 JSON 後才映射至 MCP 公開欄位。搜尋使用者輸入不得轉成任意 URL 或 host。

若來源回傳 401、403、429、驗證／挑戰頁、非 JSON 或上游 schema 不相容，立即停止該次來源請求，回傳明確的來源錯誤類別並記錄不含正文的診斷。不得自動改用代理、輪替 IP、登入帳號、重用使用者 Cookie、破解 CAPTCHA 或持續重試挑戰頁。

## 資料範圍

- 僅搜尋公開職缺，不處理求職者履歷、會員資訊、帳號資料、投遞紀錄或私人聯絡資訊。
- 每筆結果標示 `104` 資料來源、104 職缺 reference、來源網址及擷取時間。
- 只回傳工作搜尋所需的職稱、公司、地點、薪資原文、摘要、條件及詳情欄位；保留來源原文的語意，不推測缺失欄位。
- 職缺描述、公司介紹及上游文字都視為不可信資料，不得作為 MCP 工具指令。
- 第一版不提供登入、收藏、追蹤、投遞或對平台寫入的功能。
- V1 不建立定期全站抓取、永久資料庫、搜尋索引或訓練資料集；不記錄完整職缺正文。

## 快取、速率與日誌

- V1 不持久保存完整職缺內容；工具回應只在單次請求期間存在於記憶體。
- 每個 MCP 呼叫限制最大頁數、頁面大小、總筆數、單次請求時間與輸出字元數。
- 來源請求採單一 adapter 節流，避免 MCP client 重試放大上游流量；只對連線錯誤及明確可重試的暫時性錯誤進行有限重試，不對 4xx、驗證頁或挑戰頁重試。
- 診斷可記錄 correlation ID、工具、來源、HTTP 狀態類別、耗時和筆數；不得記錄憑證、Cookie、完整使用者提示或完整職缺正文。

## 來源狀態

| 來源 | V1 狀態 | 技術方式 | 限制 |
|---|---|---|---|
| 104 | 實作中／啟用後查詢 | 網站 JSON 搜尋與詳情端點；curl-impersonate 相容 HTTP client | 非穩定公開 API 契約；網頁端點及回應格式可能變動；遇拒絕即停止 |
| Cake | 已啟用（唯讀） | Cake 公開職缺搜尋頁的內嵌 Next.js 資料；遇到 challenge 明確回報來源錯誤 | 每筆標示 `cake:` reference、原始連結和擷取時間；不登入、不使用 Cookie、不處理 CAPTCHA |

本文件描述本專案選定的工程策略，不代表來源平台背書或保證端點可用。任何改變資料類型、登入狀態或寫入操作的功能，都必須另行規劃與審查。
