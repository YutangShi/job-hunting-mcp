# Spec Delta

## Purpose

讓求職者以當次提供的技能、經歷與偏好評估職缺適配度，輸出可解釋的符合項目與缺口；分析不得保存個人資料，也不得冒充錄取或薪資決策。

## ADDED Requirements

### Requirement: 匹配工具必須使用最小化的當次候選人資料

`match_jobs_to_profile` SHALL 接受明確的技能、年資、地點、薪資與工作型態偏好，資料只在單次請求處理期間使用，不得寫入日誌、檔案、資料庫或來源平台。

#### Scenario: 以技能匹配職缺
- **WHEN** 使用者提供技能與有效 job_ref 清單
- **THEN** 系統回傳每筆職缺的匹配分數、符合技能、缺口、計分依據、來源與 `fetched_at`

#### Scenario: 沒有提供個人資料
- **WHEN** 使用者未提供任何可匹配的 profile 欄位
- **THEN** 系統拒絕請求並說明至少需要一項技能、經歷或偏好，不猜測候選人背景

### Requirement: 匹配結果必須可解釋且不得過度承諾

匹配結果 MUST 分離來源事實與推論，揭露缺少的職缺欄位、使用的權重及資料新鮮度；不得輸出錄取機率、保證薪資或歧視性結論。

#### Scenario: 職缺缺少薪資
- **WHEN** 匹配偏好包含最低薪資但職缺沒有公開薪資
- **THEN** 系統將薪資匹配標示為 `unknown`，不判定為符合或不符合

#### Scenario: 產生排名
- **WHEN** 使用者要求依匹配度排序
- **THEN** 系統依揭露的規則排序，並允許使用者看到每項加減分原因

### Requirement: 薪資分析必須標示可比較性

`analyze_salary` SHALL 僅使用公開薪資欄位，區分月薪、年薪、區間、面議、未提供與不可解析值，並在樣本不足時標示 `insufficient_sample`。

#### Scenario: 分析薪資區間
- **WHEN** 多筆職缺提供同一地區與職類的可解析薪資
- **THEN** 回傳統計摘要、樣本數、幣別／期間與逐筆來源

#### Scenario: 薪資格式不一致
- **WHEN** 職缺混合月薪、年薪或面議
- **THEN** 系統分組或標示不可比較，不直接合併成單一平均值
